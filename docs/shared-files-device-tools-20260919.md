# 共享文件与设备批量管理

## 共享文件

左侧“共享文件”和系统托盘提供入口。客户端读取服务端真实目录，支持面包屑导航、上传、下载、新建文件夹、同目录重命名，以及删除文件或空文件夹。删除前页面要求确认；不会递归删除目录或覆盖同名文件。失败时显示服务端错误。

默认共享区为 `R-Link-Server/shared/`，已加入 Git 忽略列表。可通过 `R_LINK_STORAGE_DIR` 指定其他绝对路径，重启服务生效。接口继续使用现有本机访问限制和服务访问密钥；远端使用需先配置服务监听地址、密钥和客户端 API 地址，详见 README。

每个文件最多 64 MiB，每个目录最多读取 2000 个条目。原始请求体流式上传，超过限制时取消写入；只有完整落盘后才发布最终文件，同名提交原子拒绝。路径检查拒绝绝对路径、父目录跳转、Windows 特殊名称、数据流路径、符号链接、目录联接和硬链接。下载使用附件响应，密钥仅放在 API 请求头中。

共享区由服务端管理员维护，部署时应使用独立目录和单个服务进程，不应与不可信的本地用户共用可修改的目录。上传原子发布需要文件系统支持硬链接（Windows NTFS 和常用 Linux 文件系统支持）；不支持时报告失败。并发操作在单个服务进程中串行提交。

这不是远程设备的 SFTP/WebDAV 浏览器，也不创建点对点连接。文件保存在当前连接的 R-Link Server 上。客户端离开文件页会取消未完成的传输；没有断点续传或后台下载队列。桌面下载由 WebView 处理，Windows 实测默认保存至当前用户“下载”目录。

## 设备工具

- 搜索名称、地址或用户名，按未检测、可达、不可达筛选。
- “检测筛选结果”只检查当前筛选出的登记设备，最多并发 4 个请求，不扫描整个子网。单台失败不会中止其余设备，显示进度和失败原因。
- “停止检测”或离开页面会停止后续调度、取消客户端请求；已被服务端接受的检查可能完成并保存结果。
- 导出从后端读取最新清单，仅保存 `name`、`host`、`port`、`username`。密码、私钥、数据库 ID 及旧检测结果不会导出。
- 导入先预览条目数量、确认后提交。已有主机/端口组合及文件内重复条目跳过，旧配置不覆盖。字段校验失败或总数超过 256 台时整批回滚，不产生半份清单。客户端导入文件限制为 1 MiB。

格式示例（示例地址，不会自动登记）：

```json
{
  "version": 1,
  "devices": [
    { "name": "我的服务器", "host": "192.0.2.10", "port": 22, "username": "admin" }
  ]
}
```
