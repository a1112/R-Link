# 桌面驻留、群晖安装与 R-File 服务复用

用户要求本机编译打开、常驻任务托盘、开机自启、NAS 等系统安装版本及 R-File 互动。用户确认 NAS 为群晖 DSM，并指定自动使用 R-File 的网络服务。当前 R-File 仓库记录 DS918+ / DSM 7.1.1 / apollolake，型号尚未由本次用户另行确认，因此以此构建明确标识架构的包，不声称所有型号实测。

## 桌面

保留现有原生托盘、关闭驻留、单实例唤回和 SSH 生命周期。接入 Tauri 官方 autostart 插件，设置与托盘菜单读取系统实际启用状态、提供启停和错误提示。自启参数为 --autostart，托盘可用时隐藏，托盘失败则显示；用户主动打开或再次运行仍显示窗口。普通首次运行不自动更改开机配置。本机安装到稳定路径后按用户要求启用，再验证实际注册路径和参数。

## R-File

复用已有 rfile-watch 文件服务和 rfile-bridge 网络服务，兼容 RFILE_SERVICE_URL、RFILE_BRIDGE_URL 等现有约定，默认自动检查本机 18080 / 18100，不额外启动或复制 R-File 进程。远端由服务器配置地址，不做子网扫描。健康检查必须识别真实 R-File 协议。R-Link 用专用控制端身份与现有 bridge 通信，登记后心跳、读取其设备和会话状态；不修改其他设备信任/策略，不宣称形成 VPN。

R-File 文件能力使用现有 API；仅在管理员配置凭据和共享根目录后启用目录浏览、上传、下载。令牌仅留在服务端，禁止输出到状态、日志、浏览器或 URL。桥接凭据持久保存在当前服务数据目录并限定权限，不借用桌面进程内存中的私密令牌。默认不开放全盘，不递归删除/覆盖，不绕过 R-File 自身权限。保留现有 R-Link 共享区。

API 与页面显示检测时间、未启动、鉴权失败、远端断开及权限限制；状态来自 R-File。所有带凭据请求禁用重定向，限制时长、响应大小和传输尺寸，路径不得逃逸指定共享根。连接取消和应用关闭释放 HTTP 资源。

## 安装与分发

Windows 提供更新的 NSIS 包。Linux/NAS 提供含前后端源码、Compose、配置模板和安装/升级说明的可构建安装包，支持 amd64/arm64 的原生 Docker 构建。群晖提供 Docker 运行方式，若 Docker 环境和打包条件满足则制作 apollolake DSM 7.1 的 SPK 生命周期包装器与离线镜像。NAS 启动服务、重启恢复、卷持久化和卸载保留用户数据均验证；任何未编译/未实测架构明确标注。

不把云端控制面误当作设备端 VPN；跨网接入仍使用既有网络服务能力及其策略。NAS 若只装了 RFileNAS watch 而无 bridge，报告文件服务可用、网络服务未启动。

## 验证

先验证新增行为失败，再实现及回归。Windows 实测关闭驻留、重复唤回、自启参数、退出；Docker 实测健康、鉴权、写入与重启持久化。真实 R-File bridge 进行注册/设备读取/心跳，文件服务验证隔离目录传输。NAS 实机不可达时报告限制，不能把离线包校验当作 DSM 安装成功。新功能经需求审查和代码质量审查后整合至用户本机主工作区。
